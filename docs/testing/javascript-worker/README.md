# iOS JavaScript Worker 可行性验证

2026-11-03：在专用 iOS 26.5 模拟器的独立调试应用中验证宿主现有 `react-native-webview` 与 `react-native-nitro-http-server`。测试只运行内置、已核对的两个书源脚本，桥接请求均由内存假响应完成，没有访问书源网站，也没有修改原生代码或生产小程序。

- 直接加载 HTML 时，Worker 可执行现代 JavaScript，死循环可终止，但页面和 Worker 均没有 `SharedArrayBuffer`，见 [截图](ios-blob.png)。
- 临时本机服务返回 `Cross-Origin-Opener-Policy: same-origin` 和 `Cross-Origin-Embedder-Policy: require-corp` 后，页面及 Worker 均可使用 `SharedArrayBuffer`；Worker 在 `Atomics.wait` 中等待 RN 回调，再恢复执行。Node 本机服务测试见 [截图](ios-loopback-node.png)；随后改用调试应用内已有的 Nitro HTTP 服务，结果见 [截图](ios-native-server.png)。
- [最终验证](ios-default-source.png) 使用 1321 集合的「伪书香」原始搜索脚本，以及默认 7663 源的两个搜索表达式。模拟的 `java.post`、`cookie.removeCookie`、`java.ajax` 和 `java.encodeURI` 均完成同步往返，预期搜索地址正确；人工死循环递增共享计数，调用 `terminate()` 后两次读取的计数不再变化，新 Worker 仍能响应。编码样本仅为中文，不能推断完整 Java 表单编码兼容性。
- 单独在同一隔离调试进程启动两个 Nitro HTTP Server 实例：第二个启动后第一个端口不再响应，第二个端口正常，见 [共存测试截图](ios-server-conflict.png) 和 [测试入口](worker-server-conflict-probe.txt)。测试版本是调试应用中的 1.9.2；宿主 1.10.0 源码也使用进程级全局服务器状态，但其运行行为尚未实测。
- 本轮增加共享监听器：Worker 页面复用当前 Web 或 MCP 服务的端口，使用随机路径、隔离响应头和独立租约；关闭一方时保留仍在使用的另一方。隔离 iOS 模拟器的原生 HTTP Server 和 WKWebView 共完成 8 项检查，包括共享端口、公共路由、隔离响应头、拒绝 POST、`SharedArrayBuffer`、停止公共服务、手动恢复及外部占用保护，见 [截图](ios-shared-listener.png) 和 [测试入口](shared-listener-probe.txt)。该测试使用独立进程中的临时服务，没有接入真实书源执行流程。
- 继续将引导页面和 Worker 脚本分开提供：页面只允许同源 Worker，Worker 响应独立设置 `worker-src 'none'`、`connect-src 'none'` 和 COEP。最初遗漏 Worker 自身的 COEP 时它无法在隔离页面启动；补上后，隔离模拟器中共享缓冲、现代 JavaScript 求值、同步宿主回复和终止忙循环通过，同一本机地址上的 `fetch`、同步 XHR、`importScripts`、动态导入和子 Worker 探测均被阻止，服务端没有收到探测请求，见 [截图](ios-worker-csp.png) 和 [测试入口](worker-csp-probe.txt)。
- CSP 并未阻止同源 `BroadcastChannel`：Worker 能向页面发消息，见 [截图](ios-worker-channel.png)。另一个仅供探索的启动代码在求值前遮蔽该构造器及可配置的原型属性，测试中的直接访问、原型查找和 `Function` 查找均未取回构造器，见 [截图](ios-worker-channel-guard.png) 和 [测试入口](worker-channel-guard-probe.txt)。这只是有限样本，并非完整的沙箱或旁路安全证明，且限制代码尚未接入正式运行时。
- 新增独立的 Worker 会话及静态页面原型，使用任务编号、顺序调用编号、大小限制、取消和分阶段超时。专用模拟器的独立调试应用使用这些代码执行同步假桥接、默认 7663 搜索表达式、取消等待中的宿主调用、死循环超时及后续任务，结果见 [截图](ios-worker-session.png) 和 [测试入口](worker-session-probe.txt)。默认源的网络结果仍为假数据；通道遮蔽只验证有限样本，不构成安全沙箱。原型没有接入正式书源流程，亦未验证真实宿主或物理手机。
- 搜索脚本适配原型已接上现有 `SourceJavaScriptBridge` 的 Ajax、POST、Cookie 清理及 Java 表单编码，POST 提供状态、地址、正文和不区分大小写的响应头查询。专用 iOS 模拟器中的独立调试应用使用原始 7663 搜索表达式及 1321「伪书香」POST 脚本，配合模拟网络响应检查搜索结果、GBK 编码、死循环超时及后续任务，见 [截图](ios-worker-bridge.png) 和 [测试入口](worker-bridge-probe.txt)。测试没有连接源站；它只覆盖这些接口的部分输入，尚未实现完整 Java 对象、字节数组、变量和 DOM 等接口。变量的后续支持见下方记录。取消后适配器会丢弃迟到响应，底层请求是否终止取决于外部桥接的取消信号。该原型仍未接入正式书源流程。
- 响应桥接原型为每次任务登记原始宿主响应，并将 Worker 返回的响应对象映射回原始对象，添加了 `java.connect`、浏览器验证和提示接口。在专用模拟器中，以模拟的 403 和验证结果执行 7663 原始登录检查，确认原始和重试响应的对象身份、普通对象与响应的区分、POST 头读取，以及脚本改写 `JSON.parse` 的有限测试，见 [截图](ios-worker-login.png) 和 [测试入口](worker-login-probe.txt)。桥接在运行脚本前捕获部分内建方法，但这些测试不证明 Worker 能安全执行不可信代码；正式调用方仍须检查返回对象的身份，完整隔离和其他 Java 接口均未完成。
- 会话现提供页面失效和替换操作：停止旧任务及其桥接调用，并拒绝旧页面标识的消息和迟到的页面失败事件。专用模拟器中实际卸载并重建了两次 WebView，验证等待中的调用取消、新页面执行、旧消息忽略及手动模拟页面失效后的恢复，见 [截图](ios-worker-lifecycle.png) 和 [测试入口](worker-lifecycle-probe.txt)。这个测试没有实际终止 WKWebView 内容进程；正式组件必须在替换前生成全新随机标识，并把对应标识传给页面失败回调，自动重载和进程退出的接线仍未完成。
- 新增队列执行原型，将会话与每任务独立的书源桥接和响应登记表组合起来；排队任务可以单独取消，失败后继续处理后续任务，页面不可用及释放时会拒绝等待任务。专用 iOS 模拟器用模拟响应并发提交 7663 搜索表达式和 1321「伪书香」脚本，验证串行执行、登录响应身份、排队和运行中取消及恢复，见 [截图](ios-worker-executor.png) 和 [测试入口](worker-executor-probe.txt)。这不是实际源站或正式书源流程测试，执行器尚未嵌入应用；底层请求能否中止仍取决于桥接调用者传入的取消信号。
- 实际搜索函数现在允许调用方注入异步执行器；默认仍使用原执行器，搜索 URL 脚本、模板表达式和登录检查均将取消信号传给注入的执行器。专用模拟器的独立调试应用通过此接口接入 Worker，使用模拟首页和搜索页面执行 7663 的真实搜索及结果解析，并模拟 403、浏览器验证完成和重试，见 [截图](ios-worker-search-flow.png) 和 [测试入口](worker-search-flow-probe.txt)。验证回调自动返回测试数据，并非真实人机验证；未访问源站或真实 HTYF 宿主。目录和正文的同步提取规则仍使用现有执行器，正式应用没有启用 Worker，`js-interpreter` 和 `re2js` 尚未移除。
- 发现、详情、目录和正文请求也允许注入登录检查执行器；目录和正文的多页请求逐页传递执行器和取消信号。专用 iOS 模拟器通过实际页面函数及模拟的 7663 响应，验证搜索、发现、详情、目录和两页正文，七次请求的登录检查与两个搜索表达式均交给 Worker，见 [截图](ios-worker-pages-flow.png) 和 [测试入口](worker-pages-flow-probe.txt)。本测试的内容提取规则仍使用现有同步解析器，正式应用也尚未注入 Worker；没有访问源站或真实宿主。
- Worker 增加 `java.get/put` 与 `source.get/put/getVariable/setVariable/putVariable` 桥接，书籍变量复用流程中的 Map，书源变量复用现有持久化接口；保持变量数量、大小限制，并将存储错误作为规则失败。专用模拟器使用隔离存储命名空间，配合模拟网络运行 1321「小小阅读」和「全本小说」原始搜索规则，验证搜索与登录变量共享、恢复的源变量、持久化往返及 `undefined`/`NaN` 转换，见 [截图](ios-worker-variables.png)、[测试入口](worker-variables-probe.txt) 和两份书源副本 [小小阅读](source-xiaoxiao.json)、[全本小说](source-quanben.json)。搜索结果的同步提取仍使用原执行器；测试没有访问真实站点或宿主。
- Worker 原型可通过现有规则查询器执行 `java.getString`、`java.getStringList` 和 `java.setContent`，保留 URL 解析、解码重载、列表方法、递归规则拒绝及查询预算。专用 iOS 模拟器对照现有解析器，检查正文规则示例、重定向地址、列表、解码、内容替换、嵌套规则和超限后的恢复，见 [截图](ios-worker-lookup.png) 和 [测试入口](worker-lookup-probe.txt)。测试使用内存页面，没有访问源站；DOM 的后续支持见下方记录，同步规则的异步改造尚未完成，原型仍未启用在正式应用中。
- DOM 桥接原型使用每任务的节点引用表，支持 `java.getElement/getElements`、元素和元素列表的 `attr/text/html/select`、列表方法，以及将选中元素用于后续查询。专用模拟器在内存 HTML 上执行 1321「二三中文」与「笔趣阁」原始目录脚本，验证章节数据、返回节点身份、嵌套选择、JSON 查询、非法选择器和脚本覆盖数组方法的一个防伪样本，见 [截图](ios-worker-dom.png)、[测试入口](worker-dom-probe.txt)、[二三中文](source-ersan.json) 和 [笔趣阁](source-biquge.json)。测试未访问源站；混合返回值和输入节点的后续支持见下方记录，有限的防伪样本不代表完整脚本隔离。
- 增加有界的返回值编码，允许节点、响应和普通值混在数组或嵌套对象中返回，并在宿主恢复登记过的原对象；普通对象中相似的字段不会自动变成引用。专用 iOS 模拟器验证混合及嵌套节点、响应身份、普通对象、`undefined`/`NaN` 和循环对象错误，见 [截图](ios-worker-graph.png) 和 [测试入口](worker-graph-probe.txt)。深度与项目数受限；输入节点的后续支持见下方记录，完整 JS 对象语义仍未验证，测试没有访问源站或真实宿主。
- 新增有界输入编码，将规则选中的节点、普通对象和数组传入 Worker，并在输入图中保留重复引用。专用 iOS 模拟器对照现有同步规则，验证选中节点方法、`src === result`、嵌套输入往返、普通对象与节点的区分、循环输入拒绝及后续恢复，见 [截图](ios-worker-input.png) 和 [测试入口](worker-input-probe.txt)。输入内容仍有大小和深度限制，超大原始页面的惰性访问、所有规则上下文及异步规则链尚未实现；正式应用仍未启用 Worker。
- 规则解析器现在共用一套分阶段执行逻辑，保留同步接口并增加可等待脚本执行器的异步接口；新增适配器把规则上下文、查询器和变量传给 Worker。专用 iOS 模拟器以本地 HTML 执行 1321「二三中文」和「笔趣阁」原始目录规则，并对照同步结果验证脚本与选择器衔接、模板执行顺序、选中节点和源变量，见 [截图](ios-worker-async-rule.png) 和 [测试入口](worker-async-rule-probe.txt)。这只验证独立调试入口，未访问真实网站或宿主。
- 正文加载函数支持显式注入异步规则执行器，用于正文、副内容、翻页地址和替换规则，同时传递取消信号；默认仍使用原同步执行器。专用 iOS 模拟器将该接口连接 Worker，使用模拟的两页响应验证规则阶段、正文替换和变量传递，见 [截图](ios-worker-content-rule.png) 和 [测试入口](worker-content-rule-probe.txt)。页面实际调用方尚未注入执行器。测试不涉及源站、真实宿主或真机。
- 目录加载函数也支持显式注入异步规则执行器；同步和异步目录共享章节构建步骤，保留顺序、变量作用域、分页和取消处理。专用模拟器把 Worker 接入目录加载函数，使用本地页面响应执行 1321「二三中文」和「笔趣阁」的原始目录脚本，检查章节顺序及脚本写入的书籍变量，见 [截图](ios-worker-toc-rule.png) 和 [测试入口](worker-toc-rule-probe.txt)。自动测试另覆盖多页变量和取消。此测试没有访问源站，正式页面仍未注入 Worker，真实宿主尚未验证。
- 并发目录页的异步解析原先可能交错，导致一页的书籍变量被另一页章节读取。现在同一次目录加载中的解析步骤依响应到达顺序排队，下载仍可并发；等待中的解析收到取消后立即拒绝，并在轮到时跳过；解析失败时后续排队脚本不会启动。专用 iOS 模拟器以模拟响应验证两个请求同时进行、两个目录页的脚本各自读回正确变量，见 [截图](ios-worker-toc-concurrency.png) 和 [测试入口](worker-toc-concurrency-probe.txt)。自动测试覆盖变量交错、排队取消和脚本失败。
- 登录检查也可能在另一页的异步解析期间覆盖书籍变量。目录加载现将每页的登录检查与解析作为连续步骤排队，同时保留原始请求并发。专用模拟器通过 Worker 执行模拟源的登录检查及目录脚本，确认两个请求并发且每页章节使用本页登录检查写入的变量，见 [截图](ios-worker-toc-login-concurrency.png) 和 [测试入口](worker-toc-login-concurrency-probe.txt)。自动测试另验证登录检查从网络错误恢复。该验证使用模拟响应，真实站点、浏览器验证及真实宿主仍未验证。
- 详情加载函数现支持显式注入异步规则执行器，同步与异步解析共用字段提取顺序；保留变量、可选元数据容错、目录缓存和取消行为。专用 iOS 模拟器连接 Worker，使用模拟 JSON 验证初始化、简介、书名、作者、分类与目录脚本以及缓存复用，见 [截图](ios-worker-info-rule.png) 和 [测试入口](worker-info-rule-probe.txt)。自动测试还对照同步解析的下载链接和元数据容错。此测试不访问源站或真实 HTYF 宿主，正式页面仍未启用 Worker。
- 搜索与发现加载函数现可显式注入异步规则执行器；列表字段、每本书的变量、直接跳转详情及缓存复用都使用同一套同步/异步解析步骤。专用 iOS 模拟器通过 Worker 和模拟响应验证搜索、发现、直达详情、目录缓存与变量，见 [截图](ios-worker-search-rule.png) 和 [测试入口](worker-search-rule-probe.txt)。自动测试覆盖取消与旧同步行为。真实站点、宿主及不可信脚本隔离仍未验证，正式页面未启用 Worker。
- 修正 Worker 输出检查与发送之间的重复读取：普通对象和数组现在发送已经验证的编码快照，避免 getter 在检查后返回不同内容；节点数组也通过同一编码保留身份。单独或嵌套的 `NaN`、`Infinity`、`-Infinity` 和负零可正确往返。专用 iOS 模拟器通过实际 Worker、WebView 和 RN 桥验证对象及数组 getter、特殊数值和 DOM 节点列表，见 [截图](ios-worker-snapshot.png) 和 [测试入口](worker-snapshot-probe.txt)。这些有限检查不能证明 Worker 是安全沙箱。
- 书源调试流程允许调用者显式传入同一个异步脚本执行器和取消信号，并依次传递给搜索、详情、目录和正文。专用 iOS 模拟器使用 Worker 与本地模拟响应完整运行四个调试阶段，验证阶段事件、详情、正文及脚本调用，见 [截图](ios-worker-debug-flow.png) 和 [测试入口](worker-debug-flow-probe.txt)。自动测试也覆盖详情阶段取消；书源调试页面尚未创建或注入 Worker，测试未访问源站或真实宿主。
